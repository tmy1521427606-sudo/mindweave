# 知脉按需生成今日日报设计

## 目标

在现有单机版知脉中增加一个由用户主动触发的日报生成闭环。用户早上可以选择今日关注方向、减少方向、临时关键词，并可选填写对昨日内容的点评；所有输入均可跳过。只有点击“生成今日日报”后才联网搜索并调用豆包，生成过程预计 3～8 分钟，完成后形成 10～30 条可回溯内容。

## 范围

本期包含：

- 首页顶部的“今日生成台”。
- 手动触发生成、阶段进度和明确失败原因。
- 昨日优先、最近七天补充的联网检索。
- 个性化筛选、来源核验、去重和结构化解读。
- 同一天多版本、重新生成和只补充新内容。
- 已完成版本在重启后保留，并立即进入现有日报、详情和搜索体验。

本期不包含：

- 定时任务、后台自动生成和断点续传。
- 自动提交或推送 GitHub。
- 账号、多人使用、跨设备同步和云端任务队列。
- 生成中的人工逐条编辑、取消按钮和半成品预览。

## 用户流程

首页日报导航之前显示“今日生成台”。生成前提供四项可选输入：

- `focusMore`：今天多看的主题，多选。
- `focusLess`：今天少看的主题，多选；与 `focusMore` 互斥。
- `temporaryFocus`：临时关注文字，最多 300 字，只影响本次生成。
- `yesterdayComment`：昨日点评，最多 1000 字；可形成低权重、随时间衰减的长期信号。

所有输入可以为空。点击“生成今日日报”后按钮锁定，同一进程同一时间只允许一个任务。界面按顺序展示：准备偏好、联网搜索、去重筛选、来源核验、生成解读、保存日报，并显示候选数、完成条数和耗时。未核验的半成品不展示为正式日报。

当天已有日报时提供：

- `full`：重新生成完整新版本。
- `supplement`：保留当前条目，只补充去重后的新条目，总数仍不超过 30。

重新生成前明确提示会再次产生模型和搜索费用。

## 架构

采用现有 Node 进程内任务，不引入外部队列。新增独立的日报生成服务，持有内存任务表并协调偏好、Tavily、豆包、文件归档和 SQLite 同步。前端创建任务后每两秒轮询状态。

服务关闭会中止运行中的任务；已完成版本不会丢失。任务状态只保留到本次进程结束，不作为可恢复工作流。

主要接口：

- `POST /api/daily-generations`：验证输入并创建任务，返回 `202` 和 `jobId`。
- `GET /api/daily-generations/:jobId`：返回阶段、计数、耗时、完成结果或安全错误。
- `GET /api/issues/:date/versions`：返回该日期的版本列表和当前版本。

浏览器不接收任何供应商密钥。

## 搜索与生成

搜索主题至少覆盖电商 × Agent、数据 × Agent、金融 × 科技、Agent 开发与大模型、新模型发布与对比，以及知识图谱、本体论、Wiki、Multi-Agent 等热门技术。

第一轮检索上海时区的前一自然日。可靠候选不足 10 条时扩展到最近 7 天；仍不足时允许加入相近领域报告或热门基础技术，并标记为 `contentType: learning` 和 `isBackfill: true`。不能用低质量结果凑满 10 条；无法达到最低可靠数量时整次任务失败并说明内容不足。

系统使用中英文查询收集多于最终数量的候选，再规范化 URL、标题、发布日期和来源，按规范 URL与近似标题去重。来源优先级为：

1. 公司官方公告、官方文档、GitHub Release、论文和政府机构。
2. 可信技术媒体及行业研究报告。
3. 其他公开来源仅作线索，不能单独支撑确定事实。

不抓取公众号全文，不使用付费墙正文。Tavily 可返回正文摘录，但本机服务不直接请求任意搜索结果 URL，从而避免 SSRF 面。

豆包先在候选中选择可靠内容，再按小批次生成统一的日报字段。输出必须通过确定性校验：来源为 HTTPS、日期合法、事实可映射到来源、枚举和评分范围正确、事实/来源观点/系统推断分离。单批失败重试一次；最终只保存全部校验通过的正式结果。

## 个性化与多样性

现有 SQLite 兴趣画像继续提供长期主题权重和解释深度。今日选择仅用于当前任务：`focusMore` 提高候选排序，`focusLess` 降低候选排序，但重大事件仍可入选。

非空昨日点评由豆包提取最多五个已知主题的方向信号，每个主题只能为 `-1` 或 `+1`，并保存到 SQLite。生成时使用半衰期 14 天的指数衰减；点评对单条候选的总影响限制在 `[-2,+2]`，低于现有明确兴趣按钮。原始点评只保存在本机数据库，不写入日报 JSON 或 Git。

为避免信息茧房：

- 单一主题不超过最终条目的 40%。
- 至少覆盖三个主要方向。
- 重大模型或行业事件可越过个人偏好进入日报。
- 重复技术必须具有新事件或新的分析角度。
- “我已很了解”降低基础解释深度，不屏蔽主题。

## 版本与持久化

每次成功生成一个不可变版本：

```text
data/2026-09-11-v1.json
data/2026-09-11-v2.json
```

`data/index.json` 对每个日期仍只有一个条目，`file` 指向当前版本，并增加 `currentVersion` 与 `versions` 元数据。旧的无版本文件继续兼容。SQLite 只同步当前版本，避免归档搜索返回同一事件的多个版本。

写入顺序为：校验完整 payload、写临时版本文件、原子重命名版本文件、原子替换 index、调用现有 `syncIssueDirectory`。index 只在版本文件就绪后更新，因此失败不会覆盖当前日报。孤立但未被 index 引用的文件不进入应用。

## 错误与费用控制

未同时配置 `ARK_API_KEY`、`DOUBAO_CHAT_MODEL` 和 `TAVILY_API_KEY` 时禁用生成按钮，并显示缺少的配置类型，不显示密钥值。

搜索方向部分失败时可继续；模型单批失败重试一次。整体失败分类为：未配置、搜索失败、模型失败、超时、内容不足、输出校验失败和保存失败。API 只返回安全错误，不泄露响应正文、文件路径或密钥。

任务目标时间为 3～8 分钟，服务端硬超时为 10 分钟。达到硬超时后失败，不继续产生调用。界面在创建任务前提示会产生 API 费用；完成状态记录搜索调用数和模型调用数，不承诺精确人民币金额。

## 验证标准

- 空输入可创建任务；重复点击不能创建第二个并行任务。
- 首轮仅搜索昨天，候选不足才扩展到七天。
- 有可靠资料时生成 10～30 条；不足时明确失败且不写半成品。
- 每条满足现有日报字段、来源、日期、评分和内容分类校验。
- 单主题占比不超过 40%，至少覆盖三个主要方向。
- 点评信号低权重、14 天半衰期，并且不污染今日临时选择。
- full 和 supplement 均创建新版本；旧版本可切换，当前版进入 SQLite 搜索。
- 重启后已完成版本存在；运行中任务无需恢复。
- 浏览器、导出、日志、JSON 和 Git 中无 API Key。
- 模拟供应商的自动化测试不产生真实费用，现有 170 项测试继续通过。
